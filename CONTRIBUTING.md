# Как внести вклад в bitrix-ai-toolkit

Рады и людям, и AI-агентам. Проект — про качественную и производительную разработку под 1С-Битрикс, поэтому вклад ценим
конкретный: правила, скиллы, проверки, адаптеры под новых агентов.

## Быстрый старт
```bash
git clone https://github.com/vgtitov/bitrix-ai-toolkit && cd bitrix-ai-toolkit
sh onboard/install.sh --no-tools     # хуки + скиллы + сборка + самотест
python3 tests/test_bitrix_guard.py   # должно быть 4/4
```

## Архитектура (важно понять до PR)
- **Правь `core/`, не сгенерированное.** Единый источник — `core/` (AGENTS.md, skills, linters, mcp). Файлы в корне
  (`CLAUDE.md`, `AGENTS.md`, `.mcp.json`, `.claude/`) **генерируются** командой `sh build.sh` — руками их не редактируют.
- Три оси переносимости: **AGENTS.md** (правила) + **SKILL.md** (навыки) + **MCP** (инструменты). Новый агент —
  тонкий адаптер в `adapters/<agent>/`, не форк ядра.
- Claude Code — эталонная реализация; при добавлении фич сначала работает в ней, потом раскладывается адаптерами.

## Что приветствуется
- Новые/уточнённые **правила** по реальному коду ядра (со ссылкой на dev.1c-bitrix.ru или исходники — не «по памяти»).
- **ast-grep правила** и проверки на анти-паттерны Битрикс (с фикстурой в `tests/fixtures/` и тестом).
- **Скиллы** и references (кэш, производительность, безопасность, миграции) — формат SKILL.md.
- **Адаптеры** под новых AI-агентов.
- Улучшения `onboard`/`build.sh`, документации, CI.

## Правила для PR
1. **Обезличенность.** Никаких внутренних данных организаций, реальных доменов клиентов, секретов. Проект намеренно обезличен.
2. **Проверяемость, не «по памяти».** Факты о Битрикс — со ссылкой на справку/исходники. Непроверенное помечай `[проверить]`.
3. **Тесты зелёные.** Новая проверка = фикстура (`tests/fixtures/`) + тест. `python3 tests/test_bitrix_guard.py` → 4/4 (и твои новые).
4. **Хуки проходят.** commit-msg (чистые сообщения) + pre-commit (bitrix-guard N+1). Тест-фикстуры с намеренным
   анти-паттерном коммить с `git commit --no-verify` и пометкой в сообщении.
5. **`sh build.sh` без ошибок**, сгенерированные файлы соответствуют `core/`.
6. Стиль: без жаргона, «заголовок = вывод», честные оговорки. По-русски (проект русскоязычный).

## Процесс
Форк → ветка `feat/...` или `fix/...` → изменения в `core/` → `sh build.sh` → тесты → PR по шаблону.
Мелкие правки доков — можно напрямую PR. Крупные изменения архитектуры — сначала issue на обсуждение.

## Для AI-агентов
Этот репозиторий **agent-friendly**: читай `AGENTS.md` (правила) и `docs/AI_INSTALL_GUIDE.md`. Можешь открывать issue и
PR. Соблюдай те же правила: правь `core/`, добавляй тест на каждую проверку, не коммить секреты, факты — по коду/справке.
