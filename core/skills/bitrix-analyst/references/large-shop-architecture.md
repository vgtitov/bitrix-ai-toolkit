# Архитектура крупного Битрикс-магазина — слои (обезличенно)

Что понимать при анализе задач крупного магазина. Ядро Битрикс часто обёрнуто внешними слоями — не искать баг «в Битрикс»,
если функция реализована снаружи.

## Слой данных (Битрикс)
- **Инфоблоки** (каталог, контент) + **Инфоблоки 2.0** на объёмах; **торговые предложения (SKU/offers)** — вариативные
  товары (размер/цвет); **highload-блоки** — справочники/характеристики; **catalog** — цены (типы цен), склады, остатки;
  **sale** — корзина, заказы, скидки/правила корзины, оплата/доставка.
- **Регионализация:** город из GeoIP → cookie `BITRIX_SM_GEOIP_CITY_*`; цены/наличие/сроки по городам; кэш по региону+типу цены.

## Внешние обёрточные слои (НЕ чисто Битрикс — частый источник путаницы)
- **1С-обмен (CommerceML):** товары/ТП/цены/остатки/заказы приходят из учётной 1С; **XML_ID = GUID из 1С** — ключ
  сопоставления (не автоинкремент Битрикс). Изменения структуры каталога согласовывать с форматом обмена.
- **Внешний поиск/рекомендации** (Elastic/OpenSearch/Meilisearch или SaaS) — при 1M+ SKU поиск и автоподсказки вынесены
  наружу; Битриксу — только рендер. Баг подсказок ищи во внешнем сервисе, не в `search.title`.
- **CDN/edge-прокси** (Cloudflare и др.) — edge-кэш, WAF, HTTP/2-3, спекулятивный prefetch. Влияет на «почему не видно
  изменений», кэш-заголовки, композит.
- **Битрикс24-CRM/омниканал** — лид-формы (`crm/site_button`), Открытые линии, онлайн-чат. Отдельная интеграция.
- **Аналитика/dataLayer** — GTM/GA/Метрика/пиксели, e-commerce события корзины/заказа (часто трогает фронт).
- **SEO-слой** — микроразметка Schema.org (Product/Offer), canonical, ЧПУ каталога с сегментом-ТП.
- **Ресайз изображений** — `iblock` + `resize_cache` (`CFile::ResizeImageGet`), webp-пайплайн.

## Масштабирование
- **Веб-кластер** (модуль cluster): несколько web-нод, общий Redis-кэш и сессии, репликация БД master-slave, балансировка.
- Признаки снаружи: стабильный низкий TTFB под нагрузкой, отсутствие сессий на статике/композите.

## При анализе задачи спрашивай (влияет на архитектуру)
Объём каталога (инфоблоки 2.0? фасет?), число типов цен/регионов (кэш, нагрузка), где поиск (Битрикс vs внешний),
есть ли 1С-обмен (структуру менять с оглядкой на CommerceML), CDN/композит (отладка), нагрузка (кластер).
