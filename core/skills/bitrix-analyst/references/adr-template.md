# ADR — шаблон (Architecture Decision Record)

Заводить ADR, если решение: **(а)** трудно откатить, **(б)** затрагивает нескольких разработчиков,
**(в)** выбирали между вариантами. Формат — Nygard, короткий. Хранить в репозитории проекта (`docs/adr/ADR-00N-*.md`).

---

```markdown
# ADR-007: Хранение характеристик товара в highload-блоке вместо свойств инфоблока

Дата: 2026-07-24 · Статус: Принято (заменяет ADR-003)

## Контекст
230 тыс. товаров, 40 характеристик. Свойства инфоблока дают JOIN на каждую характеристику;
страница фильтра — 4.2 с (замер perfmon, ссылка на замер). Фасетный индекс умного фильтра
не покрывает часть множественных значений.

## Решение
Характеристики → highload-блок `ProductFeatures`, связь по `ELEMENT_ID`, доступ через
`Local\Catalog\Domain\FeatureRepository` (порт), адаптер на D7 ORM. Фильтр — через Specification
→ filter адаптера.

## Рассмотренные альтернативы
1. Оставить свойства + фасетный индекс — не покрывает множественные значения.
2. ElasticSearch — избыточно для текущего объёма, +узел в инфраструктуру.

## Последствия
+ Фильтр 4.2 с → ~0.4 с (замер после — приложить).
+ Домен не зависит от способа хранения (можно уехать в ES позже — только адаптер).
− Нужна миграция данных (скрипт + откат) и правка выгрузки из 1С.
− Админка редактирования характеристик — своя (типовой формы нет).

## План миграции
1. Миграция структуры HL (sprint.migration) — обратимая.
2. Скрипт двойной записи (свойства + HL) на 1 неделю.
3. Переключение чтения через feature-флаг в Option.
4. Удаление свойств отдельной задачей после проверки.

## Техдолг
Админ-форма характеристик — заглушка (задача #421, срок Q4).
```

---

## Правила заполнения
- **Контекст — с фактами и замерами**, а не «было медленно». Ссылка на perfmon/лог/график.
- **Альтернативы обязательны** (минимум одна) с причиной отказа — иначе это не решение, а декларация.
- **Последствия честно, и плюсы, и минусы.** ADR без минусов не вызывает доверия.
- **План миграции с откатом** — если решение меняет данные/структуру.
- **Статус** живой: Предложено → Принято → Заменено ADR-N / Отклонено. Старые не удалять — история решений ценна.
- **Техдолг явно**, со ссылкой на задачу в трекере.
