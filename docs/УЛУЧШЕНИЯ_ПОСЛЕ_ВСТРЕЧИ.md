# План улучшений после встречи 24.07.2026

Источник: встреча с командой разработки + явные требования Славы. Транскрипт записи анализируется отдельно
(`2026-07-24 10-03-23.mov`, 58 мин) — находки подмешиваются по мере готовности.

## Ключевая боль встречи
**Разработчики боятся, что контролёры качества ухудшат им жизнь** (обязательные гейты, синхронные проверки на команду).
Ответ toolkit: **все проверки опциональны и настраиваемы**, по умолчанию не ломают процесс; каждый может гонять
проверки AI на СВОИХ частях кода независимо, не навязывая команде. Плюс — знания о качестве зашиты в скилл, чтобы
AI писал корректно **даже без запуска проверок**.

## Задачи

### 1. Опциональность проверок (без потери качества) — P0
- [ ] `config/checks.toml` — единый конфиг: какие проверки включены (phpstan/cs-fixer/ast-grep/guard), режим
      (`off`/`warn`/`block`), scope (пути), уровни. По умолчанию — мягко (warn, не block).
- [ ] Env-оверрайды (`BITRIX_AI_CHECKS=off|warn|block`) и graceful skip, если инструмент не установлен.
- [ ] Хуки читают конфиг: pre-commit по умолчанию `warn` (не блокирует), включается в `block` осознанно.
- [ ] Документ «как включить/выключить/настроить под себя», как гонять только на своих путях.

### 2. Внутренние знания о качестве (AI знает без запуска проверок) — P0
- [ ] `core/skills/bitrix-dev/references/quality-standards.md` — свод правил качественного Битрикс-кода
      (что бы поймал линтер), чтобы AI писал корректно проактивно: именование, структура компонента/модуля,
      работа с инфоблоками/ORM, кэш, безопасность, частые ошибки. Со ссылками на dev.1c-bitrix.ru.
- [ ] Ссылка из SKILL.md bitrix-dev на этот свод как «читать перед написанием».

### 3. Кастомные изменения ядра — P0
- [ ] `core/skills/bitrix-dev/references/custom-core.md` — как работать с проектами, где ядро `/bitrix` ИЗМЕНЕНО
      (не только `/local`): как это фиксировать, версионировать патчи ядра, диффать с эталоном версии, риски
      обновления, как toolkit это учитывает (scanDirectories на реально изменённое ядро).
- [ ] Поле в `config/version-stack.toml`: `core_modified = true/false` + путь к патчам ядра.

### 4. Токен-экономия — P1

### 6. Per-company конфиг в отдельной репе (будущее) + работа standalone — P1
- [ ] `config/local/` (в `.gitignore`) — слой локализации компании: версии, пути ядра, правила проверок, креды.
- [ ] `docs/LOCALIZATION.md` — как хранить настройки компании в отдельном private-репо (team-repo), который мы
      инициализируем; toolkit подхватывает его через env-путь. **Без него всё работает на дефолтах и не ломается.**

### 7. Проверка (verify-by-running) — P0
- [ ] Реальный онбординг на Mac: `onboard/install.sh --no-tools` → самотест.
- [ ] Реальный тест использования: дать AI писать/понимать Битрикс-код на демо-репо, проверить корректность и что
      проверки срабатывают опционально. Прогнать на Mac; при необходимости — Work PC/Server PC.
- [ ] Исправить некорректное, задокументировать, показать вывод.

## Принципы
- Ничего не ломается в ходе эксплуатации: все новые части — опциональны, с безопасными дефолтами, graceful degradation.
- Настройки компании отделяемы (отдельная репа), но toolkit самодостаточен без них.
- Знания зашиты так, что AI пишет качественно даже при выключенных проверках.
