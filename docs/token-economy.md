# Токен-экономия — как не жечь контекст

Правила, зашитые в архитектуру toolkit. Дешевле всего то, что агент **не читает**.

## Главный приём: хуки вместо диалога
`PostToolUse`-хук гоняет PHP-CS-Fixer + PHPStan **сам**, детерминированно. Агент не тратит токены на «запусти линтер →
прочитай вывод → повтори». Формат `--error-format=json` даёт компактный машинный список `{файл, строка, message}`
вместо простыни текста. **Это 80% экономии.**

## Поиск: от дешёвого к дорогому
1. **Grep/ripgrep** (встроенный) — самый дешёвый: находит строку/символ без чтения файлов целиком. Первый выбор.
2. **ast-grep** — структурный поиск по AST; дороже grep, но точнее там, где важна структура (анти-паттерны).
3. **Serena `find_symbol`** — символьная навигация; читает не файл, а **символ** (метод/класс) — дешевле, чем `Read`
   всего файла. Ограничивай область `--project` (`/local` + нужные модули), НЕ индексируй всё `/bitrix`.
4. **Read целиком** — только когда действительно нужен весь файл.

## Что НЕ делать
- Не читать ядро `/bitrix/modules` целиком «чтобы понять» — ищи точечно (grep → символ).
- Не гонять MCP-раундтрип там, где хватает CLI с JSON-выводом (PHPStan через хук дешевле, чем phpstan-MCP «по запросу»).
- Не тащить в контекст весь вывод линтера — `--error-format=json` + фильтр по изменённым файлам.
- Не дублировать: правила живут в `AGENTS.md`/скиллах (грузятся по необходимости), а не копипастой в каждый промпт.

## Прогрессивное раскрытие (формат SKILL.md)
Скилл устроен так: метаданные (~100 токенов) всегда в контексте → тело (<5k) грузится при срабатывании → `references/`
читаются только по нужде. Поэтому глубокие материалы (кэш, каталоги, диагностика) вынесены в `references/`, а не в тело.

## Настройки, влияющие на расход
| Настройка | Эффект |
|---|---|
| `BITRIX_AI_CHECKS=off` | проверки не запускаются вовсе — минимум токенов, но и качество только на знаниях скилла |
| режим `warn` (дефолт) | проверки идут, вывод компактный, агент не зациклен на блокировках |
| Serena `--project` узко | резко меньше индексации и выдачи |
| `scope.paths` в `checks.toml` | проверки только по своим путям — меньше шума и токенов |

## Практика для больших Битрикс-баз
Ядро — десятки тысяч файлов. Никогда не «показывай агенту весь проект». Рабочий цикл: grep по симптому → прочитать
1-2 нужных символа/файла → правка → хук проверил → готово.
